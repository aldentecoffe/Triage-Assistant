# Данные

## Политика

- Реальные данные оператора, персональные данные и коммерческая тайна не используются.
- Основной источник — синтетический генератор инцидентов по доменной модели
  телеком-инфраструктуры.
- Публичный корпус IT-заявок используется как внешний источник для проверки переноса
  и предобучения представлений. Перед использованием проверяется лицензия.
- Анонимизированная выгрузка инцидентов — только при наличии письменного разрешения;
  она не должна быть обязательной зависимостью проекта.

## Схема датасета

Версия 1.1 — смена `data/interim/incidents_clean_v1.1.csv`: 6 000 строк, 20 столбцов,
UTF-8. Единица анализа — карточка одного инцидента. Несколько карточек одного каскада
связаны через `event_id` и независимыми объектами не считаются. Критичность — свойство
карточки: в одном событии карточки могут описывать разный масштаб влияния, таких событий
430 из 4 097.

| Поле | Роль |
|---|---|
| `description` | Единственный признак для TF-IDF и поиска похожих |
| `severity`, `service`, `root_cause` | Три метки: критичность, сервис, категория причины |
| `scenario_id`, `event_id`, `text_hash` | Группировка и проверка разделения, в признаки не входят |
| `split`, `rights_status`, `synthetic`, `source` | Служебные: выборка, допуск, маркировка, происхождение |
| `title` | Отображение, в модель не входит |
| `incident_id`, `created_at`, `source_system`, `region`, `affected_ci`, `language`, `generator_version`, `dataset_version` | Аудит |

Типы, допустимые значения и разбор персональных данных: [docs/lab4/schema.md](../docs/lab4/schema.md).
Состав, ограничения и репрезентативность: [docs/lab4/data_card.md](../docs/lab4/data_card.md).
Проверки качества и анализ: [docs/lab5/quality_review.md](../docs/lab5/quality_review.md),
версия Data Card 1.1: [docs/lab5/data_card_update.md](../docs/lab5/data_card_update.md).
Разметка и версия 1.1: [docs/lab6/annotation_guideline.md](../docs/lab6/annotation_guideline.md),
[docs/lab6/data_card_update.md](../docs/lab6/data_card_update.md).

## Таксономия версии 1.1

Сервисы: `transport`, `platform`, `database`, `ims`, `billing`, `bss`, `external`.
Категории причин: `change`, `capacity`, `hardware`, `software`, `network`, `external_dep`.
Критичность: P1 — ключевая клиентская функция не выполняется, обходного пути нет
(голос и регистрация в сети, платежи, доступность магистрали); P2 — функция не выполняется
для части объектов или недоступна отдельная функция/интеграция; P3 — деградация, задержка
или очередь с обходным путём; P4 — абоненты не затронуты (мониторинг, отчётность,
справочники). Правило целиком: [инструкция разметчика](../docs/lab6/annotation_guideline.md),
раздел 3.

Черновик из лабораторной 1 с 12 сервисами и 10 категориями причин не отменён, а отложен
до версии 2.0: при 6 000 записей редкие категории получают меньше 300 примеров. Причины
изменения и план расширения перечислены в [docs/lab4/schema.md](../docs/lab4/schema.md).
