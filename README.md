# SRE Triage Assistant

ML-сервис автоматического триажа инцидентов для SRE-команды телеком-оператора.

> Учебный проект. Сервис помогает дежурному инженеру быстрее понять, что произошло,
> насколько это критично и кто должен заниматься инцидентом.

## Статус

Лабораторные 1–2 — проектирование и организация работы: [проектный план](docs/project-plan.md),
[команда и роли](docs/team-and-roles.md). Лабораторная 3 — ноутбук по CRISP-DM на данных
Wine Quality. Лабораторная 4 — данные проекта: реестр источников, схема, Data Card v1, стратегия
разделения и генератор на 6 000 записей. Лабораторная 5 — разведочный анализ и проверки
качества: 19 проверок, восемь графиков, Data Card 1.1. Лабораторная 6 — разметка и
подготовка данных: инструкция разметчика, пилот на 150 карточках и 30 повторных,
расчёт согласия (каппа 1,00 между проходами; совпадение с набором 0,925 по критичности
и 0,953 по сервису и причине), подготовка признаков без утечки из test, Data Card 1.2.
Код сервиса и модели появятся в лабораторных 7–8.

## Проблема

В крупном телеком-операторе дежурная смена получает поток инцидентов из разных систем
мониторинга и ITSM. Первичный триаж — определение критичности, затронутого сервиса и
вероятной причины — часто выполняется вручную, занимает время и зависит от опыта инженера.
Ошибки маршрутизации увеличивают MTTR.

## Что делает сервис

По текстовому описанию инцидента (заголовок и описание, опционально источник мониторинга
и регион) сервис возвращает:

- **критичность** — P1–P4 с оценкой уверенности;
- **затронутый сервис/домен** — например, биллинг, BSS/OSS, HLR/HSS, транспорт,
  платформа Kubernetes;
- **вероятную категорию корневой причины** — изменение/деплой, инфраструктура, сеть,
  ёмкость, внешняя система, ошибка конфигурации и т. п.;
- **топ-3 похожих инцидентов** из истории — как подсказку по runbook (план).

Сервис не принимает решение за инженера: он даёт структурированную подсказку и снижает
время первичного разбора.

## Данные

- Основной источник — синтетический генератор инцидентов по доменной модели
  телеком-инфраструктуры (6–10 тыс. записей). Версия 1.1 — 6 000 записей после очистки,
  28 сценариев отказов, 7 сервисов, 6 категорий причин. Критичность выводится из
  формулировки последствия по правилу инструкции разметчика, а не разыгрывается.
- Публичный корпус IT-заявок — для проверки переноса и предобучения представлений.
  [IT Service Ticket Classification Dataset](https://www.kaggle.com/datasets/adisongoh/it-service-ticket-classification-dataset).
  Лицензия не подтверждена, в расчётах не используется.
- Реальные данные оператора, персональные данные и коммерческая тайна не используются.
  Анонимизированная выгрузка — только при наличии разрешения.

Реестр источников, схема и Data Card: [docs/lab4](docs/lab4/). Пайплайн:

```bash
python src/generate_incidents.py --count 6000
python src/prepare_dataset.py
python src/split_dataset.py
python src/eda_incidents.py
python src/prepare_features.py
python src/triage_baseline.py run
python -m pytest tests -q
```

`eda_incidents.py` печатает таблицу из 19 проверок, пишет `docs/lab5/quality_checks.csv`
и восемь графиков в `docs/lab5/figures`; файлы данных он не меняет.
`prepare_features.py` считает словарь и IDF только по train и пишет
`docs/lab6/features_manifest.json`, по которому видно состав признаков.
`triage_baseline.py run` оценивает два baseline ЛР 7 и пишет отчёты в `docs/lab7`. Поиск
по произвольному тексту: `python src/triage_baseline.py search --query "рост таймаутов Diameter"`.

Подробнее: [data/README.md](data/README.md).

## Целевые метрики

| Задача | Метрика | Цель |
|---|---|---|
| Критичность | F1-macro / recall P1 | ≥ 0,75 / ≥ 0,90 |
| Сервис | F1-macro / top-3 accuracy | ≥ 0,80 / ≥ 0,90 |
| Корневая причина | F1-macro | ≥ 0,65 |
| Сервис | время ответа | < 1 с на инцидент |

## Ограничения

- Синтетические данные ограничены шаблонами; качество на реальных инцидентах требует
  отдельной валидации.
- Сервис — помощник, а не замена дежурному инженеру и промышленным ITSM/AIOps-платформам.
- Проект учебный; он не содержит конфигураций и данных оператора.
