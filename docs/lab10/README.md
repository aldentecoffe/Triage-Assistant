# Лабораторная 10: архитектура и инструменты

Задание — принять архитектурное решение до реализации alpha-версии: матрица
минимум из трёх альтернатив, схема компонентов с полями и резервными путями,
перечень инструментов с версиями и ADR с допущениями.

## Что решали

Поиск похожих инцидентов выбран и измерен в ЛР 7–9. Не решено было другое: откуда
alpha берёт три метки — критичность, услугу и корневую причину. До этой работы их
не производил ни один модуль.

Ответ: три разных источника, каждый выбран по измерению на 1 200 карточках
validation.

| Метка | Источник | F1-macro | Цель плана |
|---|---|---|---|
| Критичность | правило по таблице последствий (84 фразы) | 1,000 | 0,75 |
| Услуга | голосование по трём ближайшим карточкам | 0,301 | 0,80 |
| Корневая причина | логистическая регрессия на TF-IDF | 0,266 | 0,65 |

Критичность упирается в определение метки из ЛР 6, поэтому единица измеряет
согласованность с правилом разметки, а не умение оценить серьёзность инцидента.
Цели по услуге и причине не достигнуты: это записано как ограничение в ADR.

## Как воспроизвести

```bash
python src/arch_check.py run      # измерение, 6–7 секунд
python src/arch_check.py figure   # схема компонентов
```

Модуль читает только train и validation, поле `test_used` в отчёте равно `false`.
Если словарь расходится с `docs/lab6/features_manifest.json`, прогон падает: другой
словарь означал бы другой эксперимент.

Машинные результаты: `results/check.json`, схема: `figures/architecture_flow.png`.
Время в блоке `latency` (и поле `gates.latency_p95_ms`, которое из него берётся)
меняется от прогона к прогону, остальные блоки совпадают, поэтому сверять стоит
выбор, варианты и ворота, а не миллисекунды.

## Что измерено

| Проверка | Значение |
|---|---|
| Полный проход на инцидент | около 2 мс медиана, около 2,5 мс p95, до 5 мс максимум |
| Сборка индекса при старте | 0,2–0,3 с |
| Обучение трёх моделей | 0,4–0,5 с |
| Индекс | 3 600 × 3 799, 136 340 ненулевых, 1,57 МБ |
| Сверка с ЛР 9 | точность классификатора причины 0,369167 совпала до шестого знака |
| Флаг «соседи разошлись» (услуга) | точность 0,346 против 0,174 |
| Порог по вероятности у причины | не помогает: F1 0,202 против 0,266 |
| Повторный прогон | все поля совпали, кроме времени: p95 2,34 и 2,35 мс |

## Чего в отчёте нет

Test не читался: он израсходован в ЛР 9 как контроль после замороженного решения.
Причины `network` в validation нет, поэтому её F1 равен нулю по построению. Все 96
карточек P1 относятся к одному сценарию. Локальные embeddings не сравниваются
числами: модель не выбрана, качество и ресурсы не измерены, и в матрице стоит
«неизвестно», а не оценка.
