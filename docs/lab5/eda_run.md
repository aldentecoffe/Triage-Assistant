# Воспроизводимый анализ: как запустить

Лабораторная 5, артефакт проекта. Дата: 2026-11-23.

Разведочный анализ отвечает на восемь вопросов, от которых зависят признаки, разделение
выборок и оценка моделей. Логика лежит в [`src/eda_incidents.py`](../../src/eda_incidents.py),
представление — в ноутбуке [`lab5_incident_eda.ipynb`](../../notebooks/lab5_incident_eda.ipynb).
Оба используют один и тот же код, поэтому цифры в ноутбуке и в репозитории совпадают.

## Запуск

Из корня репозитория:

```bash
python src/generate_incidents.py --count 6000
python src/prepare_dataset.py
python src/split_dataset.py
python src/eda_incidents.py
```

Первые три команды пересобирают набор из seed 20261123: 6 008 сырых карточек, 8 исключённых,
6 000 очищенных, три файла выборок. Четвёртая команда ничего не пересобирает, только читает
готовые файлы.

Ноутбук запускается отдельно:

```bash
jupyter nbconvert --to notebook --execute --inplace notebooks/lab5_incident_eda.ipynb
```

В Colab первая ячейка клонирует репозиторий и прогоняет пайплайн, если файлов данных нет.
Сети, кроме GitHub при клонировании, скрипт не требует.

## Что скрипт проверяет

19 проверок разбиты на четыре группы.

Целостность: объём raw и clean, состав трёх выборок против clean (нет ли потерянных,
лишних или повторённых между выборками карточек), схема из `REQUIRED_COLUMNS`, пустые
обязательные поля, уникальность `incident_id` и `affected_ci`, совпадение `text_hash`
с пересчитанным хешем, допустимые значения меток, журнал исключений с причинами
и затёртыми текстами без прав.

Разделение: пересечение `scenario_id`, `event_id` и `text_hash` между train, validation и test,
каскадные пары в одной выборке, покрытие сервисов и причин по выборкам, согласованность
события (критичность карточки совпадает с классом её последствия, разброс времени не больше
30 минут).

Объём и текст: поддержка классов по выборкам, длина описания, повтор шаблонов после
нормализации чисел, номеров CI и имён узлов, доля заголовков, собранных из слов описания.

Связи с меткой: перенос словаря train на validation и test, Cramer's V для служебных полей,
дециля `affected_ci` и `scenario_id`, период и покрытие по времени.

Пустой вход тоже даёт «проблему»: проверки не пишут «ок» на пустом наборе.

## Решения, которые держат цифры на месте

Набор детерминированный: генератор не использует системное время и сеть, все значения
разыгрываются от seed. Очистка идёт в фиксированном порядке проверок, поэтому причина
исключения у каждой записи одна. Графики строятся из тех же CSV, что и проверки, без ручных
правок. Если меняется генератор или таксономия, набор получает новую минорную версию,
прежние цифры пересчитываются, а реальная выгрузка даст версию 2.0 — это записано
в Data Card и в стратегии разделения.
