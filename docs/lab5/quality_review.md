## Что означают четыре предупреждения

Предупреждений четыре, причин три: отсутствие `network` в validation даёт две строки —
покрытие меток и поддержка классов.

`network` в validation. Два сценария с этой причиной попали в train и test, в validation
её нет ни в одной карточке. Это известное ограничение разделения из лабораторной 4, а не
дефект очистки. Практическое следствие: F1 по причине на validation считается по пяти
категориям, а вывод по `network` делается на кросс-валидации train.

Серии шаблонов. 6 000 карточек сводятся к 749 шаблонам после замены чисел, номеров CI и
имён узлов заглушками. 737 серий покрывают 5 988 карточек, и ни одна серия не пересекает
выборки. Это значит, что при случайном разделении почти у каждой карточки test был бы
почти-двойник в train. Групповой split по сценарию эту лазейку и закрывает; `text_hash`
один с ней не справился бы, потому что видит только точные копии.

Номер CI. `affected_ci` выглядит нейтрально, префикс у всех один, но номера выданы счётчиком
в порядке генерации, и диапазоны группируются по сценарию: Cramer's V дециля номера с сервисом
0,62, с причиной 0,51. Если передать номер в модель как число, она выучит сценарий. Поле
остаётся журнальным атрибутом.

## Просмотр примеров

Примеры выбраны из сырого и очищенного набора программно, без ручного отбора, чтобы не
прятать неудобные случаи.

| Пример | Записи | Что видно | Решение |
|---|---|---|---|
| Типичная карточка, ru | I000024 | «Падает BGP-сессия с пирингом; BGP_Peers_Established 1 шт…» — симптом, значение метрики, последствие, CI | полный текст годится как вход модели |
| Та же формулировка, en | I000120 | «BGP session with the upstream peer keeps flapping…» — структура та же, язык другой | один векторизатор на оба языка |
| Точный дубль | I000143, I004109 | одинаковый `text_hash`, разные `incident_id` | вторая карточка снимается очисткой |
| Права не подтверждены | I001509 | текст совпадает с I001196, но `rights_status=unknown` | журнал затирает текст, запись в clean не попадает |
| Пустое описание | I005014 | строка из пробелов, значащих символов 0 | фильтр длины обязателен в API |
| Каскад | I000019, I001554, I005100 | одно событие E000001, сервисы billing и transport | из выдачи похожих соседей по событию исключаем |
| Почти-дубликат | I000050, I000079 | один шаблон, разные значения метрики и номера CI | `text_hash` их не видит, различает нормализация шаблона |

Карточек, у которых есть хотя бы один сосед по событию, 3 125 из 6 000 (52,1 %); событий из
двух и больше карточек 1 235, а 1 890 — это карточки сверх одной на событие. Для поиска
похожих важно первое число: top-3 без фильтра по `event_id` будет отдавать вторую карточку того
же происшествия, и оценка такого поиска окажется завышенной.

## Влияние на дальнейшие шаги

- Набор остаётся версией 1.0: пересборка не требуется, объём и журнал исключений совпадают
  с Data Card v1.0.
- Признаки: только `description`. `title`, `affected_ci`, `scenario_id`, `event_id`,
  `source_system`, `region`, `language`, `created_at` в модель не входят.
- Метрики: F1-macro по каждой задаче, recall P1 отдельно, интервал — блочный бутстрэп
  по сценариям.
- Поиск похожих: исключение карточек того же `event_id`.
- ЛР 6: первый baseline — TF-IDF по словам и символьным n-граммам с линейной моделью.
