## Пройденные проверки

19 проверок, результат прогона: 15 «ок», 4 «внимание», 0 «проблема». Полная таблица с фактами
и решениями: [`quality_review.md`](quality_review.md), машиночитаемая копия:

Подтверждено:

- объём, схема и журнал исключений совпадают с версией 1.0; причины исключений: 3 без прав,
  2 пустых описания, 3 точных дубликата;
- три файла выборок в сумме дают очищенный набор: ни одна карточка не потеряна, не задвоена

- ключи `incident_id` и `affected_ci` уникальны, `text_hash` совпадает с пересчитанным;
- группы `scenario_id`, `event_id` и `text_hash` не пересекают train, validation и test;
- каскадные пары не разъехались, события не противоречат себе по критичности и времени;
- в каждой выборке есть все семь сервисов;
- недели покрыты без пропусков; равномерность по неделям видна на графике, время в признаки
  не входит.

## Исключения

Состав и порядок не изменились: 3 записи без подтверждённого допуска, 2 с пустым описанием,
3 точных дубликата по `text_hash`. Журнал: `data/interim/cleaning_log_v1.0.csv`.
Тексты записей без прав затёрты, в очищенный набор они не попадают.

## Перенос словаря

Измерено на уровне данных, без обучения модели:

| Выборка | Токенов, известных словарю train | Карточек с покрытием 80 % и выше |
|---|---|---|
| validation | 60,1 % | 2,8 % |
| test | 62,7 % | 0,0 % |

По сервисам test покрытие от 54 % (transport) до 70 % (bss). Читается так: общий словарь
у выборок есть, знакомых формулировок почти нет. Модель сможет переносить отдельные слова
и каркас фразы, но не готовые шаблоны. Ограничение 1 версии 1.0 («шаблонная генерация»)
измерено на уровне словаря, но не снято: насколько этого хватит модели, покажет ЛР 6.

## Шаблоны и почти-дубликаты

После замены чисел, номеров CI и имён узлов 6 000 карточек сводятся к 749 шаблонам.
Серий из двух и больше карточек — 737, они покрывают 5 988 карточек (99,8 %).
Ни один шаблон не встречается в двух выборках и ни один не обслуживает два сценария.
При случайном разделении почти у каждой карточки test был бы почти-двойник в train, поэтому
групповой split по сценарию остаётся обязательным.

## Proxy-признаки

| Поле | Максимум Cramer's V с метками | Решение |
|---|---|---|
| `source_system`, `region`, `language`, код региона из имени узла | 0,04 | сигнала нет, в модель не идут |
| дециль `affected_ci` | 0,62 с сервисом, 0,51 с причиной | номер выдан по порядку генерации, в признаки не идёт |
| `scenario_id` | 1,00 с сервисом и причиной, 0,17 с критичностью | служебный ключ, в признаки не идёт |

В модель идёт только `description`. `title` повторяет слова описания у 100 % карточек
и как отдельный признак не используется. `event_id` нужен для группировки и для фильтра
в оценке поиска похожих.

## Оставшиеся ограничения

1. Метки по-прежнему задаёт генератор, а не эксперт; согласие разметчиков не измерено.
2. В validation нет категории `network`: вывод по ней возможен только на кросс-валидации train.
3. Перенос измерен на уровне токенов. Символьные n-граммы и лемматизация могут изменить
   картину, это проверяется в ЛР 6.
4. Нормализация шаблонов — эвристика: она ловит одинаковые формулировки с разными числами,
   но не смысловое сходство.
5. Реальные инциденты оператора не использовались; продуктовые метрики набор не измеряет.
6. Доли сервисов равные, P1 — 6,9 %; в эксплуатации распределение другое, абсолютные метрики
   будут ниже.
