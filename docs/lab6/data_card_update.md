# Data Card 1.2: разметка и подготовка данных

Обновление к карточкам 1.0 ([lab4/data_card.md](../lab4/data_card.md)) и 1.1
([lab5/data_card_update.md](../lab5/data_card_update.md)). Версия набора — 1.1,
дата — 23 ноября 2026. Лабораторная 6.

## Что изменилось

| Что | Было в 1.0 | Стало в 1.1 | Причина |
|---|---|---|---|
| Происхождение `severity` | случайный розыгрыш по распределению сценария | выводится из формулировки последствия по таблице `IMPACT_SEVERITY` | случайную метку не может воспроизвести ни разметчик, ни модель; цель «F1 ≥ 0,75 и recall P1 ≥ 0,90» была недостижима |
| Раскладка сценариев по выборкам | по одному сценарию на сервис в validation и test | перераспределена: каждый класс критичности есть в train, validation и test, все причины — в train и test | в прежней раскладке в test не было ни одной карточки P1, метрика recall P1 не измерялась |
| Симптомы с причиной `software` | «новый билд», «после обновления» | описание дефекта компонента без ссылки на изменение | формулировки не отличались от `change`, граница классов была нерешаемой |
| Объём, схема, версии | 6 000 карточек, 20 столбцов | без изменений, версия набора 1.1 | — |

Тексты остальных сценариев пересчитаны генератором вместе с изменёнными: набор
детерминирован по seed 20261123, но любая правка каталога меняет поток случайных чисел.
Сравнивать тексты 1.0 и 1.1 по строкам нельзя; сравнение идёт по инвариантам и проверкам.

## Критичность

Правило версии 1.1 описано в [инструкции разметчика](annotation_guideline.md), раздел 3.
Коротко: сначала проверяется, затронуты ли абоненты и клиентские операции, затем —
выполняется ли функция, затем — есть ли обходной путь.

Распределение: P1 — 417 (7,0 %), P2 — 2 223 (37,0 %), P3 — 2 701 (45,0 %), P4 — 659 (11,0 %).

| Выборка | P1 | P2 | P3 | P4 |
|---|---|---|---|---|
| train | 4,2 % | 35,9 % | 48,3 % | 11,7 % |
| validation | 8,0 % | 46,6 % | 36,8 % | 8,6 % |
| test | 14,2 % | 31,1 % | 43,3 % | 11,3 % |

Разброс объясняется тем, что критичность привязана к сценариям, а сценарии разведены по
выборкам группами. В test P1 даёт сценарий платежей, в train — сценарий регистрации в
сети: модель проверяется на переносе класса на новые формулировки, а не на запоминании.

## Ограничения

1. Набор синтетический. Метки критичности выведены из формулировки последствия по
   правилу, поэтому качество модели на этой метке измеряет воспроизводимость правила, а не
   качество триажа на реальном потоке. Для реальной выгрузки правило нужно согласовать с
   SRE-командой.
2. Критичность — свойство карточки, а не события: одно происшествие может быть описано
   карточками разного масштаба влияния. Таких событий 430 из 4 097. Оценка и бутстрэп
   считаются по событиям, поэтому пересечение карточек внутри события учтено.
3. P1 остаётся редким классом (7,0 %), а в test его доля выше (14,2 %) из-за группового
   разделения. Recall P1 на test измеряется на одном сценарии и не заменяет проверку на
   других формулировках.
4. Перенос словаря ограничен: validation покрывает 57,5 % токенов train, test — 58,9 %,
   карточек с покрытием 80 % и выше нет ни там, ни там. Модель проверяется на новых
   формулировках внутри знакомого словаря.
5. Разметка выполнена автором проекта. Совпадение с метками набора не доказывает, что
   правило верное: оба ответа получены одним человеком.
