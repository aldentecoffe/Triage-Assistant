# Условия прогона

Условия записаны до первого запуска и воспроизводятся командой
`python src/triage_baseline.py run`. Машинная копия таблицы со всеми отпечатками —
`results/settings.json`.

| Параметр | Значение |
|---|---|
| Данные | версия 1.1, 6 000 карточек; train 3 600, validation 1 200, test не используется |
| Индекс поиска | 3 600 карточек train |
| Запросы | 1 200 карточек validation, все без отбора |
| k | 3 |
| Признак | только `description`; `title`, `service`, `root_cause`, `severity`, `scenario_id` в модель не входят |
| Представление | TF-IDF из ЛР 6: слова и биграммы, `min_df=2`, `max_features=20000`, `sublinear_tf`; словарь 3 799 признаков |
| Сходство | косинус: скалярное произведение нормированных векторов |
| Оценка релевантности | 2 — совпали услуга и причина; 1 — совпала одна из меток; 0 — ни одной |
| Сегмент запроса | доля уникальных содержательных слов, найденных в словаре train: содержательное — без цифр и не чаще чем в 50 % карточек train; 0, до 50 %, 50–80 %, выше 80 % |
| Метрики поиска | NDCG@3 с gain 2^оценка − 1 и дисконтом 1/log2(позиция + 1); Recall@3, если в top-3 есть оценка не ниже 1; MRR@3 |
| Метрики классификации | accuracy, F1-macro и полнота по классам |
| Равные оценки | дополнительная сортировка по `incident_id` по возрастанию |
| Нулевой вектор | пустая выдача, а не случайная карточка |
| Случайность | не используется, seed не задан |
| Окружение | Python 3.12.10, scikit-learn 1.9.1, pandas 3.1.1, NumPy 2.5.5 |
| Отпечаток словаря | `44c848662e62…`, совпадает с `docs/lab6/features_manifest.json` |
| Отпечатки данных | train `d641ceb6…`, validation `73f5e83f…`, test `2181bbf4…` (SHA-256 файлов) |

Правило релевантности, метрики, набор запросов и разбиение на выборки не менялись после
первого запуска. Менялось описание сегментов, и оба изменения записаны. В первой версии
запросы делились на «все слова знакомы» и «часть слов знакома»; все 1 200 запросов попали
во вторую группу, потому что `CI-XXXXXX` и `host-...` режутся на части, а цифры в покрытие
не входят. Во второй версии служебными считались только цифровые токены, и в числителе
остались `ci` и `host`, которые есть почти в каждой карточке. Текущая версия исключает все
слова, которые встречаются больше чем в половине карточек train. Сегмент — разрез отчёта,
поэтому метрики поиска от этих правок не зависят; менялись только размеры сегментов.

После первого прогона в отчёт добавлено пояснение, что оценка 2 недостижима: пары
«услуга + причина» у train и validation не пересекаются. Это наблюдение, а не новое условие.
