# ЛР 7: baseline для проектной задачи

Нижняя граница качества для двух выходов проекта: поиска похожих инцидентов и триажа.
Baseline нужен как точка отсчёта для ЛР 8–9, а не как рабочее решение.

## Запуск

Из корня репозитория, после пайплайна данных:

```bash
python src/generate_incidents.py --count 6000
python src/prepare_dataset.py
python src/split_dataset.py
python src/triage_baseline.py run
```

Прогон печатает сводку и пишет `results/settings.json`, `results/retrieval_per_query.csv`,
`results/retrieval_metrics.json`, `results/classification_metrics.json`, `results/cases.json`,
а также `metrics.md` и `cases.md`. Повторный запуск на тех же данных даёт те же файлы.

Поиск по произвольному тексту — та же модель на том же индексе, без пересчёта validation:

```bash
python src/triage_baseline.py search --query "рост таймаутов Diameter на IMS"
python src/triage_baseline.py search --query-id I000421
python src/triage_baseline.py search --query "саксофон лаконичный"
```

Последняя команда показывает границу метода: ни одного слова из словаря train, выдача пуста.

## Что сделано

Поиск. TF-IDF и косинусное сходство. Словарь и IDF строит модуль ЛР 6
(`src/prepare_features.py`), поэтому validation не влияет ни на признаки, ни на веса.
Индекс — все 3 600 карточек train, запросы — все 1 200 карточек validation,
k = 3, вход только `description`. Точное совпадение слов без весов тоже считается
baseline, но представление признаков зафиксировано в ЛР 6, и ЛР 7 его не меняет.
Ранжировщик по разметке сложнее и требует пар «запрос — релевантная карточка», которых
в наборе нет.

Триаж. Один самый частый класс train на каждый выход: severity → P3, service → transport,
root_cause → capacity. Модель не смотрит на текст.

## Результаты

Поиск: NDCG@3 0,629, Recall@3 0,732, MRR@3 0,674, пустых выдач нет.
Из 1 200 запросов 621 получили идеальную по правилу выдачу и 322 — нулевую.
Полностью релевантная карточка (совпали и услуга, и причина) в индексе недостижима:
пары «услуга + причина» у train и validation не пересекаются (14 пар против 7, общих 0),
поэтому NDCG считается по идеалу из трёх оценок 1. Отсюда 0,629 — это порядок частично
релевантных карточек, а не доля правильных ответов.

Покрытие содержательных слов расходится по запросам от 0,154 до 0,667 при медиане 0,500;
запросов, где все такие слова знакомы словарю, нет ни одного. Разрез по покрытию показывает,
где метод держится: до 50 % — NDCG@3 0,562 и Recall@3 0,685 на 755 запросах, от 50 до 80 % —
0,742 и 0,811 на 445.

Эффективный объём выборки меньше 1 200: запросы приходят из семи сценариев, внутри сценария
карточки почти одинаковы. NDCG@3 по сценариям идёт от 0,408 (SC-PLT-03) до 0,863 (SC-BIL-02),
стандартное отклонение 0,188, полная таблица — в [metrics.md](metrics.md). Для вывода
о методе значимы семь групп, а не 1 200 строк.

Английские запросы уходят вперёд: 262 запроса дают NDCG@3 0,796 против 0,582 на 938
русских. Покрытие словаря у них близкое (0,579 против 0,524), так что разрыв не сводится
к знакомым словам.

Совпадения в выдаче: услуга в top-3 у 41,9 % запросов, причина у 38,6 %, обе метки
(разными карточками) у 7,3 %. При покрытии до 50 % услуга и причина находятся почти
одинаково часто (39,7 % и 37,5 %), при 50–80 % услуга идёт впереди (45,6 % и 40,4 %).
Причина не выигрывает ни в одном срезе: сходство держится на общих словах формулировки,
а названия услуг в описаниях встречаются редко.

Триаж по самому частому классу: severity — accuracy 0,368, F1-macro 0,135; service —
0,143 и 0,036; root_cause — 0,143 и 0,042. Для service частотная база бесполезна: в train
семь услуг с долями около 14 %. Для root_cause частота в train на validation не
переносится: capacity занимает 42,9 % train и 14,3 % validation, поэтому константа
угадывает 14,3 %. Для severity база осмысленна (P3 — 36,8 % validation, выше случайных
25 % на четыре класса), но полнота по P1 равна нулю. F1-macro считается по полному набору
меток: `network` нет в validation, класс получает 0 и уменьшает среднее — в ЛР 8 сравнение
идёт по тому же правилу.

Полные таблицы — [metrics.md](metrics.md), разбор ответов — [cases.md](cases.md).

## Что baseline не умеет

В подборке из 20 случаев сработал только механизм 3: пустых выдач нет, потому что каждый
запрос хотя бы частично покрыт словарём, а перевёрнутого порядка не встретилось — все три
карточки провала одинаково нерелевантны.

1. Не связывает словоформы. «Таймаут» и «таймауты» — разные признаки, биграммы этого
   не исправляют. Русские запросы это и показывают.
2. Не знает синонимов и перифраз. «Деградация ёмкости» и «capacity» не пересекаются,
   поэтому запрос с пересказом получает нулевую выдачу.
3. Держится за общие слова причины и последствия. В провалах все три карточки не
   совпадают ни по услуге, ни по причине, а сходство дают единицы измерения, числа
   и шаблонные обороты: в `cases.md` они перечислены для каждого случая.
4. Не различает степень похожести. Одно сходство отвечает и за услугу, и за причину,
   а признаки этих меток в тексте разные.

## Гипотезы для ЛР 8–9

1. Лемматизация русского перед TF-IDF (`spaCy` или `NLTK` из стека курса) и проверка
   прироста NDCG@3 на русском подмножестве отдельно от английского.
2. Раздельные представления: услуга по специфичным терминам, причина по универсальным,
   с последующим объединением оценок вместо одного косинуса.
3. Поиск как классификация: модель предсказывает service и root_cause, выдача
   ранжируется по совпадению предсказанных меток. Для этой ветки baseline уже дал
   точку отсчёта по F1-macro.
4. Определение похожести. Пока в индексе нет полных пар «услуга + причина», метрика
   оценивает только частичную релевантность. Либо похожесть задаётся через одну метку,
   либо схема разбиения меняется в следующей версии данных.

## Ограничения

- Данные синтетические, 28 сценариев; перенос на реальные инциденты не проверен.
- Оценки релевантности получены правилом по меткам, а не экспертной разметкой.
- Числа — точечные оценки без доверительного интервала. Запросы сгруппированы в семь
  сценариев, и разброс между ними (0,41–0,86) больше, чем любая разница внутри среза.
- В словаре остаются предлоги и служебные слова: `min_df=2` их сохраняет, и они дают
  часть сходства.
- k = 3. Переход к top-10 меняет задачу и требует пересчёта обоих вариантов.

| Файл | Что внутри |

| `metrics.md` | таблицы метрик, собраны модулем |

| `results/classification_metrics.json` | частотный baseline по трём целям |
| `results/cases.json` | подборка случаев в машинном виде |
| `tests/test_baseline.py` | 69 тестов: правило релевантности, NDCG, порядок, утечка, CLI |

с ним, то есть в родительский каталог.
