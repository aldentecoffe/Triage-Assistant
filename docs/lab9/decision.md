# Интерпретация и решение

Решение E01: **не включать**. Прирост 0,067 меньше заданных 0,10, и попадание причины в top-3 у P1 обнулилось.

Главная метрика: NDCG@3 0,413 → 0,480, прирост 0,067 при пороге 0,10.

## Проверка условий, заданных до прогона

| Условие | Результат |
|---|---|
| Прирост NDCG@3 не меньше 0,10 | не выполнено |
| Причина в top-3 у P1 не ниже baseline | не выполнено |
| NDCG@3 у P1 не ниже baseline | выполнено |
| Пустых выдач ноль | выполнено |
| Прирост не держится на одном сценарии | выполнено |

Условия взяты из карточки гипотезы работы 8: прирост не меньше 0,10, защитные показатели не ниже baseline, пустых выдач ноль, прирост не держится на одном сценарии (не больше половины общего прироста). Порог не менялся после прогона.

## Что показывает результат

Порядок изменился у 457 запросов из 1 200: лучше стало у 263, хуже — у 91. Сценарий SC-EXT-03 даёт 26 % общего прироста; остальное распределено по остальным сценариям.

Сигнал сортировки изменил выдачу так: попадание причины в top-3 выросло с 0,386 до 0,422, попадание услуги упало с 0,419 до 0,360. Рост средней метрики оплачен услугами, которые дежурный видел раньше.

Сигнал насыщен классом `capacity`: argmax — capacity у 862 из 1 200 запросов (72 %). Причина `external_dep` не распознана ни разу. Прирост 0,067 при этом распределён по причинам: change — 0,028, capacity — 0,015, software — 0,012, hardware — 0,009, external_dep — 0,003. Насыщение ограничивает интерпретацию сигнала, но не объясняет весь эффект.

Переранжирование работает там, где карточка той же причины уже попала в пул top-10, но стояла ниже. Оно не помогает запросам, у которых в пуле нет ни одной карточки той же причины, и не может поднять карточку с ранга ниже 10: потолок перестановки внутри top-10 — 0,544 из работы 8.

## Контроль на test

После фиксации решения кандидат проверен на test: NDCG@3 baseline 0,325, кандидат 0,317, прирост -0,008. Test не участвовал в выборе и решение не меняет. На других сценариях прирост не подтвердился: это ожидаемо для контроля, но означает, что переносить вывод на новые шаблоны нельзя.

## Границы вывода

- Данные синтетические: шаблоны описаний повторяются, поэтому эффект измеряет согласованность разметки и словаря, а не способность понимать реальные инциденты.
- Людей в измерении нет: ценность для дежурного и время до выбора этой таблицей не проверяются.
- P1 — один сценарий SC-IMS-03, защитный показатель P1 измеряет знакомство с его лексикой.
- Test — контроль после решения, а не второе независимое исследование: он сгенерирован тем же генератором и делит с train часть словаря, но ни один шаблон описаний не встречается в двух выборках (проверка работы 5). Поэтому test контролирует перенос на другие сценарии, а не на естественный язык.
- Гипотеза бинарна: зона 0,05–0,10 заранее объявлена отказом, поэтому «проверить дополнительно» в этом решении не используется.

## Следующий шаг

Изменение в alpha не включается: baseline остаётся основным режимом, код переранжировщика сохраняется как выключенный режим с тестами.

Следующий эксперимент должен менять другой фактор — ширину пула. Потолок перестановки внутри top-10 — 0,544, достигнутый прирост занимает 51 % этого запаса; в пуле top-25 потолок 0,616, поэтому расширение пула проверяется отдельно, а не вместе с сигналом.

Ответ на вопрос самопроверки: если главная метрика не изменится, а защитная ухудшится, изменение не включается, потому что чужой runbook в критичном инциденте дороже прироста средней метрики.
