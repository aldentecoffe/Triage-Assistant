# Работа 9. Эксперимент с улучшением

Контролируемый эксперимент E01 для проекта SRE Triage Assistant. Проверяется одна гипотеза работы 8: переранжирование пула top-10 по вероятности той же причины поднимет NDCG@3 поиска похожих инцидентов до 0,513 без падения защитных показателей. Меняется ровно один фактор — сигнал сортировки.

## Что сдаётся

| Требуемый материал | Файл |
|---|---|
| Карточка гипотезы и конфигурация запуска | `experiment_plan.md`; машинная копия — `results/config.json` |
| Журнал эксперимента | `experiment_log.md`; данные — `results/summary.json`, `results/environment.json` |
| Сравнительная таблица | `comparison.md`; машинные разрезы — `results/segments.csv`, `results/per_query.csv` |
| Интерпретация и решение | `decision.md`; машинная копия — `results/decision.json` |
| Контроль на test | `comparison.md`, раздел «Test»; `results/test_summary.json` |
| Сравнение сигналов (диагностика выбора) | `results/variants.json` |

Код изменения — `src/experiment.py`, тесты — `tests/test_experiment.py`.

## Как воспроизвести

Из корня репозитория:

```
python src/experiment.py run
python src/experiment.py variants
python src/experiment.py freeze --decision reject --reason "прирост 0,067 меньше заданных 0,10, и попадание причины в top-3 у P1 обнулилось"
python src/experiment.py test
```

`run` читает только train и validation и пишет сводку. `variants` повторяет сравнение четырёх сигналов на validation и пишет `results/variants.json`; порядок «run → variants» важен, потому что поле `matches_run` сверяет кандидата с уже посчитанной сводкой. `freeze` проверяет решение по заранее заданным условиям и записывает отпечаток сводки: решение, расходящееся с правилом, не принимается. `test` отказывается работать без `freeze` и при изменившейся сводке, поэтому test не участвует в выборе. Случайность не используется: повторный прогон даёт те же файлы.

## Результат

| Выборка | Baseline NDCG@3 | Кандидат NDCG@3 | Прирост |
|---|---|---|---|
| Validation, 1 200 запросов (отбор) | 0,413 | 0,480 | +0,067 |
| Test, 1 200 запросов (контроль) | 0,325 | 0,317 | −0,008 |

Гипотеза не подтверждена. Прирост на validation меньше заданных 0,10, а защитный показатель «причина в top-3 у P1» упал с 0,062 до 0: из 96 запросов P1 baseline находил причину у шести, кандидат — ни у одного. На test перенос не подтвердился: NDCG@3 ниже baseline, попадание причины у P1 упало с 0,439 до 0,409.

Решение E01 — **не включать**: baseline остаётся основным режимом, переранжировщик сохраняется в коде выключенным режимом с тестами. Причина отказа двойная: порог не достигнут и защитный P1 обнулился. Отдельно видно, что сигнал насыщен частой причиной: `capacity` — argmax у 72 % запросов validation, `external_dep` не распознаётся ни разу. Прирост при этом распределён: `change` 0,028, `capacity` 0,015, `software` 0,012, `hardware` 0,009, `external_dep` 0,003 из 0,067, поэтому насыщение ограничивает интерпретацию сигнала, но не объясняет весь эффект. Следующий эксперимент меняет другой фактор — ширину пула (потолок top-10 0,544, top-25 0,616), а не сигнал сортировки.

## Что проверяется

- Один изменяемый фактор: базовый поиск и кандидат считаются одним прогоном на одних данных, индексе и пуле; baseline воспроизводит NDCG@3 работы 8 до шестого знака.
- Воспроизводимость: версии, отпечатки данных, словаря и конфигурации в `experiment_log.md`; `seed` не используется; замер четырёх сигналов повторяется командой `variants` и записан в `results/variants.json`.
- Вывод не преувеличивает эффект: прирост +0,067 описан как недостаточный, отдельно показано, что он оплачен падением попаданий по услуге (0,419 → 0,360), обнулением P1 и насыщением сигнала классом `capacity`.
- Отрицательный результат не скрыт: сохранены настройки, оба прогона, примеры изменившейся и неизменившейся выдачи, разбор непокрытых классов запросов.
- Test — контроль после решения, а не второй отбор: прогон разрешён только после `freeze` и сверки отпечатка сводки.

## Границы

Данные синтетические, шаблоны описаний повторяются; людей в измерении нет; P1 — один сценарий SC-IMS-03, поэтому защитный показатель P1 измеряет знакомство с его лексикой; причина `network` в validation отсутствует; test — контроль на других сценариях, а не независимая выборка естественных запросов. Шаблоны описаний в test и train не совпадают (проверка ЛР 5), но словарь общий, поэтому test проверяет перенос на новые сценарии, а не на естественный язык. Подробности — в `decision.md`, раздел «Границы вывода».
