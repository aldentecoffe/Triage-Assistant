## Аннотация

Проект посвящён разработке ML-сервиса, который по текстовому описанию инцидента автоматически определяет критичность, затронутый сервис и вероятную категорию корневой причины. Сервис ориентирован на SRE-команду крупного телеком-оператора: он сокращает время ручного триажа, снижает число ошибок маршрутизации и помогает дежурному инженеру быстрее выбрать runbook. Результат — работающее веб-приложение с API, обученные модели, воспроизводимый пайплайн и README на GitHub.

## Цель и задачи

**Цель проекта.** Разработать и развернуть работающий ML-сервис, который по описанию инцидента выдаёт не менее трёх характеристик — критичность (P1–P4), затронутый сервис/домен и категорию корневой причины — и сопровождается README на GitHub.

**Задачи:**

1. Изучить процесс управления инцидентами и практики SRE, а также существующие решения (PagerDuty, BigPanda, Moogsoft).
2. Построить доменную модель: каталог сервисов телеком-оператора, типы отказов, правила назначения критичности.
3. Сформировать датасет: генератор синтетических инцидентов, публичные ITSM-датасеты и, при наличии разрешения, анонимизированная выгрузка.
4. Выполнить предобработку текста и разведочный анализ данных.
5. Построить и сравнить baseline-модели (TF-IDF + линейные модели, деревья решений).
6. Улучшить качество: эмбеддинги, ансамбли, подбор гиперпараметров.
7. Оценить модели, интерпретировать результаты и разобрать ошибки.
8. Реализовать сервис (FastAPI + UI), тесты, Docker и README.

## Этапы и сроки

План рассчитан на 16 недель. Ниже — этапы, их длительность и ключевые результаты.

### 1. Постановка задачи и анализ аналогов (1 неделя)

- Определение границ проекта, целевых пользователей и сценариев использования.
- Обзор SRE-практик и инструментов триажа (PagerDuty, BigPanda, Moogsoft).
- Фиксация метрик успеха и критериев приёмки.

**Результат:** утверждённый план, глоссарий, черновик каталога сервисов.

### 2. Доменная модель и сбор данных (2 недели)

- Каталог сервисов и таксономия отказов: сеть, платформа, базы данных, биллинг, BSS/OSS, внешние системы.
- Генератор инцидентов: шаблоны, сущности, правила критичности, шум и смесь русского и английского языков.
- Генерация 6–10 тыс. записей; ручная проверка 100–150 примеров.

**Результат:** генератор, CSV-датасет, описание разметки.

### 3. Предобработка и EDA (2 недели)

- Очистка и нормализация текста, обработка сокращений, путей к метрикам и смеси языков.
- Анализ распределений классов, длины текстов, частотных слов.
- Проверка дисбаланса и пересечений шаблонов.

**Результат:** ноутбук EDA, очищенный датасет, выводы.

### 4. Baseline-модели (2 недели)

- TF-IDF + LogisticRegression / LinearSVC / ComplementNB.
- Стратифицированное разделение train/val/test.
- Метрики: F1-macro, recall для P1, top-3 accuracy для сервиса.

**Результат:** таблица метрик baseline, матрицы ошибок.

### 5. Улучшение моделей (2 недели)

- Эмбеддинги (ruBERT / multilingual-e5) или SVD + ансамбли.
- Подбор гиперпараметров, class_weight, работа с редкими классами.
- Сравнение с baseline, анализ прироста.

**Результат:** финальные модели, журнал экспериментов.

### 6. Оценка и интерпретация (1 неделя)

- Оценка на отложенной тестовой выборке и golden set.
- Анализ ошибок: какие классы путаются и почему.
- Интерпретация признаков (коэффициенты, SHAP для деревьев).

**Результат:** отчёт по качеству, список ограничений.

### 7. Разработка сервиса (2 недели)

- FastAPI: /predict, /health, /similar; Pydantic-схемы.
- Загрузка моделей, предобработка, логирование.
- UI: форма ввода, карточка результата, топ похожих инцидентов.

**Результат:** локально запускаемый сервис, примеры запросов.

### 8. Тестирование, Docker и документация (2 недели)

- pytest: тесты предобработки, моделей и API; smoke-тест.
- Dockerfile + docker-compose; проверка запуска с нуля.
- README: описание, архитектура, установка, запуск, примеры, метрики, ограничения.

**Результат:** воспроизводимый запуск, README на GitHub.

### 9. Отчёт и презентация (1 неделя)

- Отчёт по этапам, методологии и результатам.
- Презентация на 10–12 слайдов, демо.

**Результат:** отчёт, презентация, демо-сценарий.

### 10. Резерв (1 неделя)

- Исправление замечаний, финальная проверка критериев.

**Результат:** проект, готовый к защите.

## Ресурсы

- **Данные:** синтетический датасет (основной); публичный корпус IT-заявок IT Service Ticket Classification Dataset (47,8 тыс. записей; https://www.kaggle.com/datasets/adisongoh/it-service-ticket-classification-dataset) — для проверки переноса и предобучения представлений; анонимизированная выгрузка инцидентов — только при наличии разрешения.
- **Среда:** Python 3.11, Anaconda, Jupyter Notebook, Google Colab, VS Code / PyCharm.
- **ML и NLP:** pandas, NumPy, scikit-learn, matplotlib, seaborn, NLTK, spaCy, PyTorch (опционально), sentence-transformers (опционально), joblib.
- **Сервис:** FastAPI, uvicorn, Pydantic, Jinja2, Docker, Postman.
- **Инженерия:** Git/GitHub, pytest, ruff (опционально).
- **Оборудование:** ноутбук; GPU не обязателен, для эмбеддингов — Colab.

## Ограничения и этика

- Только синтетические или анонимизированные данные; никаких персональных данных, коммерческой тайны и реальных конфигураций.
- Модель — советующий инструмент; финальное решение принимает дежурный инженер.
- Синтетический датасет ограничен шаблонами; качество на реальных данных требует отдельной валидации.
- Проект не заменяет промышленные ITSM/AIOps-платформы, а демонстрирует подход.
