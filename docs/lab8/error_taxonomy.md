# Таксономия ошибок

Файл собран командой `python src/eval_report.py run`. Частота всегда записана как «числитель из знаменателя»: одинаковые доли у сегментов в 96 и 559 запросов означают разное.

Типы пересекаются: один запрос может попасть в «причина не найдена» и в «ни услуги, ни причины». Складывать строки нельзя, сумма больше числа запросов.

## Что эти цифры позволяют утверждать
- Главный механизм измерен: у 552 из 1200 (0,460) запросов ближайшая карточка той же услуги ближе, чем ближайшая карточка той же причины, в среднем на 0,175. Корреляция этой разницы со средней NDCG@3 по сценариям — 0,857, по отдельным запросам — 0,512.
- Режимы выдачи объясняют среднее лучше, чем модель: «2,2,2» — 277, «1,1,1» — 298, «0,0,0» — 322. Средняя NDCG@3 — это доля каждого режима, а не одна система.
- У P1 причина не найдена 90 из 96 (0,938). Но все карточки P1 лежат в сценарии SC-IMS-03, где услуга ближе причины на 0,251. Цифра говорит о лексике этого сценария, а не о серьёзных инцидентах вообще; это ограничение измерения, а не вывод о продукте.
- Служебные слова и единицы дают больше половины косинуса у 189 из 1200 (0,158) запросов, но доля шума не отделяет провал от успеха: полосы идут 0,297 / 0,561 / 0,298, и разница между ними объясняется составом режимов, а не шумом (см. `segments.md`). Строка остаётся измеренным, но не подтверждённым объяснением.
- Медиана ранга лучшей карточки той же причины — 15: нужное рядом, но не на первых местах. Идеальная сортировка пула top-10 даёт NDCG@3 0,544, top-50 — 0,660. То есть у переранжирования есть запас, а у угадывания с первого ранга — нет.

## Ошибки вне основной выборки

Отдельно от модели: это дефекты кода, найденные специальными тестами в ЛР 7, и дефект разметки из ЛР 6. Они не входят в знаменатель основной выборки, и складывать их с ошибками поиска нельзя.

- Пустой запрос, неподдерживаемый k, пустой train, отсутствующий манифест словаря: 8 из 8 проверок отклонены или исправлены; три из восьми находок меняли опубликованные числа.
- Дефект разметки IMS-02: 3 из 150 карточек пилота; правка переносится в версию данных 1.2.
- Запросы без релевантных объектов: 0 из 1200. Такой запрос исключается из среднего и считается отдельной строкой; это правило проверено тестом на мини-корпусе.

## Чего в этой таблице нет

- Жалоб пользователей: настоящих дежурных в измерении не было, ущерб оценивается по механизму ошибки.
- Стоимости ложного срабатывания: продуктовая цель «пять минут до выбора» этой таблицей не измеряется.
- Ошибок разметки внутри validation: шкала v2 считается по меткам, а не по экспертным оценкам, поэтому ошибка метки воспроизводится в метрике как ошибка поиска.
